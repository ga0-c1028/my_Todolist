## 1. 개요 및 목적

본 문서는 인증 기반 개인 할일 관리 웹앱 "my_Todolist"의 핵심 도메인 지식을 정의한다. 특정 기술 스택에 종속되지 않는 논리적 도메인 모델을 기술하며, 개발 착수에 필요한 용어, 엔티티, 상태 규칙, 비즈니스 규칙, 유스케이스를 명확히 하는 것을 목적으로 한다.

### 배경

| 요구사항 ID | 내용 |
|---|---|
| REQ-01 | 인증된 사용자가 자신만의 할일을 개인별로 관리할 수 있는 기능이 부재하다. |
| REQ-02 | 할일에 시작일과 종료일을 함께 다룰 수 있는 기능이 필요하다. |

### 기능 요구사항 목록

| 요구사항 ID | 내용 |
|---|---|
| REQ-F01 | 회원가입 후 로그인(인증)해야 앱을 사용할 수 있다. |
| REQ-F02 | 카테고리별로 할일을 등록하며, 미지정 시 '기본' 카테고리로 간주한다. |
| REQ-F03 | 로그인한 사용자는 본인의 회원 정보를 수정할 수 있다. |
| REQ-F04 | 할일 등록 시 시작일자·종료일자를 캘린더 UI로 선택·지정할 수 있다. |
| REQ-F05 | 할일 목록을 카테고리, 시작 전, 진행중, 완료, 기한초과 기준으로 필터링할 수 있다. |
| REQ-F06 | 인증된 사용자 본인이 할일을 삭제할 수 있다. |
| REQ-F07 | 인증된 사용자 본인이 편집 화면에서 할일을 수정할 수 있다. |

## 2. 용어 정의

| 용어 | 정의 |
|---|---|
| User(사용자) | 회원가입을 통해 계정을 생성하고 로그인하여 앱을 사용하는 주체. |
| Category(카테고리) | 할일을 분류하는 단위. 사용자가 지정하지 않으면 '기본' 카테고리로 간주한다. |
| Todo(할일) | 사용자가 등록하는 작업 항목. 시작일자, 종료일자, 완료 여부를 가진다. |
| 상태(Status) | 할일의 진행 상태를 나타내는 값으로, 저장되는 속성이 아니라 시작일자·종료일자·완료 여부로부터 조회 시점에 계산되는 파생 값이다. |
| 소유자(Owner) | 특정 할일 또는 회원 정보를 생성한 사용자 본인. 해당 데이터에 대한 조회·수정·삭제 권한을 가진다. |

## 3. 핵심 엔티티와 속성

### 3.1 User
| 속성 | 설명 | 제약 |
|---|---|---|
| id | 사용자 식별자 | 필수, 고유 |
| email | 로그인에 사용하는 이메일 | 필수, 고유, 이메일 형식 준수, 가입 후 변경 불가 |
| password | 인증에 사용하는 비밀번호(해시 저장) | 필수, 최소 8자 이상 영문·숫자 포함 |
| name | 사용자 이름 또는 닉네임 | 필수, 1자 이상 30자 이하 |
| createdAt | 가입 일시 | 필수 |
| updatedAt | 정보 최종 수정 일시 | 필수 |

### 3.2 Category
| 속성 | 설명 | 제약 |
|---|---|---|
| id | 카테고리 식별자 | 필수, 고유 |
| userId | 소유 사용자 | 필수 |
| name | 카테고리 이름 | 필수, 사용자 내 고유, 1자 이상 20자 이하 |
| isDefault | '기본' 카테고리 여부 | 필수 |

### 3.3 Todo
| 속성 | 설명 | 제약 |
|---|---|---|
| id | 할일 식별자 | 필수, 고유 |
| userId | 소유 사용자 | 필수 |
| categoryId | 소속 카테고리 | 필수(미지정 시 '기본' 카테고리로 설정) |
| title | 할일 제목 | 필수, 1자 이상 100자 이하 |
| description | 할일 설명 | 선택, 최대 1000자 |
| startDate | 시작일자 | 필수 |
| endDate | 종료일자 | 필수, startDate 이상 |

| completedAt | 완료 처리 일시 | isCompleted가 true로 바뀔 때 현재 일시로 설정되고, isCompleted가 false로 되돌려지면 null로 초기화된다 |
| createdAt | 등록 일시 | 필수 |
| updatedAt | 최종 수정 일시 | 필수 |

## 4. 엔티티 간 관계

- User 1 : N Category — 한 사용자는 여러 카테고리를 가질 수 있으며, 카테고리는 반드시 한 사용자에게 소속된다.
- User 1 : N Todo — 한 사용자는 여러 할일을 가질 수 있으며, 할일은 반드시 한 사용자에게 소속된다.
- Category 1 : N Todo — 한 카테고리는 여러 할일을 포함할 수 있으며, 할일은 반드시 하나의 카테고리에 소속된다.
- 사용자별로 가입 시(또는 최초 카테고리 미지정 할일 등록 시) '기본' 카테고리가 1개 존재해야 한다.

## 5. 할일 상태(Status) 정의

할일의 상태는 별도 저장 값이 아니라, 조회 시점에 `startDate`, `endDate`, `isCompleted`(오늘 날짜 `today` 기준)를 이용해 아래 규칙으로 판단한다. 규칙은 위에서부터 순서대로 평가하며, 먼저 해당하는 조건이 상태를 결정한다.

| 순서 | 상태 | 판단 규칙 |
|---|---|---|
| 1 | 완료(Completed) | `isCompleted = true` |
| 2 | 기한초과(Overdue) | `isCompleted = false` 이고 `endDate < today` |
| 3 | 시작 전(Not Started) | `isCompleted = false` 이고 `today < startDate` |
| 4 | 진행중(In Progress) | `isCompleted = false` 이고 `startDate <= today <= endDate` |

## 6. 주요 비즈니스 규칙 및 제약조건

1. (BR-1) 인증되지 않은 사용자는 앱의 어떠한 기능도 사용할 수 없다(회원가입/로그인/로그아웃/토큰 재발급 제외). 인증되지 않은 요청은 401 Unauthorized로 응답하고 로그인 화면으로 안내한다. 토큰 재발급과 로그아웃은 access_token 없이도(만료된 상태에서도) 요청할 수 있으나, 유효한 refresh_token을 제시해야 한다.
2. (BR-2) 사용자는 본인이 소유한 회원 정보, 카테고리, 할일에 대해서만 조회·수정·삭제할 수 있다. 타인의 데이터에 접근을 시도하면 403 Forbidden으로 응답한다.
3. (BR-3) 할일 등록 시 카테고리를 지정하지 않으면 해당 사용자의 '기본' 카테고리로 자동 지정된다.
4. (BR-4) '기본' 카테고리는 사용자별로 항상 1개 존재하며 삭제할 수 없다. 단, 이름 수정은 불가하다.
5. (BR-5) '기본'이 아닌 카테고리를 삭제하면, 해당 카테고리에 속한 할일은 모두 그 사용자의 '기본' 카테고리로 자동 이관되며, 할일 자체는 삭제되지 않는다.
6. (BR-6) 할일의 종료일자는 시작일자보다 빠를 수 없다.
7. (BR-7) 완료 처리된 할일(`isCompleted = true`)은 종료일자 경과 여부와 무관하게 항상 '완료' 상태로 간주하며 '기한초과'로 분류하지 않는다.
8. (BR-8) 할일 목록은 카테고리, 시작 전, 진행중, 완료, 기한초과 기준으로 필터링할 수 있어야 한다.
9. (BR-9) 이메일은 사용자 간 중복될 수 없으며, 로그인 식별자로 사용된다. 가입 후에는 변경할 수 없다.
10. (BR-10) 회원 정보 수정 시 변경 가능한 항목은 이름(name)과 비밀번호(password)로 한정하며, 이메일은 수정 대상에서 제외된다.
11. (BR-11) 로그인 실패(이메일 미존재 또는 비밀번호 불일치)는 원인을 구분하지 않고 동일한 오류 메시지로 응답하여 계정 존재 여부가 노출되지 않도록 한다.

|---|---|---|
| 인증 | 회원가입 | 이메일, 비밀번호, 이름으로 계정을 생성한다. |
| 인증 | 로그인 | 이메일, 비밀번호로 인증하여 세션(구현상 access_token/refresh_token)을 발급받는다. |

| 회원 | 회원 정보 수정 | 로그인한 사용자가 본인의 이름, 비밀번호를 수정한다(이메일은 수정 불가). |

| 카테고리 | 카테고리 삭제 | 소유자가 '기본'이 아닌 카테고리를 삭제한다. 소속 할일은 '기본' 카테고리로 이관된다. |
| 할일 | 할일 등록 | 제목, 카테고리(선택), 시작일자·종료일자(캘린더 UI)를 입력해 할일을 생성한다. |
| 할일 | 할일 목록 조회 | 카테고리별, 시작 전/진행중/완료/기한초과 기준으로 필터링하여 조회한다. |
| 할일 | 할일 수정 | 소유자가 편집 화면에서 제목, 카테고리, 시작일자·종료일자, 완료 여부 등을 수정한다. |
| 할일 | 할일 삭제 | 소유자가 본인의 할일을 삭제한다. |
| 할일 | 할일 완료 처리 | 소유자가 할일을 완료 상태로 전환하거나, 완료를 취소해 이전 상태로 되돌린다. |
