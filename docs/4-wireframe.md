## 1. 개요 및 목적

본 문서는 인증 기반 개인 할일 관리 웹앱 "my_Todolist"의 화면 단위 와이어프레임을 정의한다. `docs/1-domain_definition.md`의 엔티티·상태 규칙·비즈니스 규칙, `docs/2-prd.md`의 기능 요구사항(FR-01~FR-13)과 범위, `docs/3-user_scenario.md`의 사용자 시나리오(SC-01~SC-11)를 근거로, 실제 화면 구현에 착수할 수 있는 수준으로 화면 목적, 관련 요구사항, UI 요소 배치, 반응형 레이아웃 차이, 주요 인터랙션을 텍스트 기반으로 기술한다. 이미지 파일 형태의 그래픽 시안은 본 문서의 범위에 포함하지 않는다.

## 2. 화면 목록

PRD 5장의 기능 요구사항과 4.1절 In Scope를 기준으로 다음 화면들을 정의한다. 로그아웃(FR-03)과 토큰 재발급(FR-13)은 별도 화면이 아니라 공통 내비게이션의 인터랙션 및 백그라운드 동작으로 처리하므로, 해당 화면 항목에서 함께 설명한다.

| 화면 번호 | 화면명 | 관련 FR | 관련 유스케이스/시나리오 |
|---|---|---|---|
| W-01 | 회원가입 화면 | FR-01 | 회원가입, SC-01, SC-08 |
| W-02 | 로그인 화면 | FR-02, FR-13 | 로그인, 토큰 재발급, SC-01, SC-04, SC-11 |
| W-03 | 할일 목록 화면(필터링 포함) | FR-08, FR-09 | 할일 목록 조회, SC-01, SC-03 |
| W-04 | 할일 등록/수정 화면(캘린더 포함) | FR-07, FR-10, FR-12 | 할일 등록, 할일 수정, 할일 완료 처리, SC-01, SC-05, SC-09, SC-10 |
| W-05 | 카테고리 관리 화면 | FR-05, FR-06 | 카테고리 등록, 카테고리 수정, 카테고리 삭제, SC-01, SC-02, SC-07 |
| W-06 | 회원 정보 수정 화면 | FR-04 | 회원 정보 수정, SC-06 |
| 공통 | 상단 내비게이션 / 로그아웃 | FR-03 | 로그아웃, SC-01 |

이 중 W-04는 할일 등록과 할일 수정이 입력 항목·레이아웃을 공유하므로 하나의 화면 유형으로 통합하여 기술하고, 등록/수정에 따른 차이는 인터랙션 항목에서 구분한다.

## 3. 공통 레이아웃 규칙

- 데스크톱 뷰(가로 폭 약 1024px 이상)는 좌측 또는 상단 고정 내비게이션과 콘텐츠 영역이 함께 노출되는 2단 구성을 기본으로 한다.
- 모바일 뷰(가로 폭 약 375px~767px)는 상단 헤더와 콘텐츠 영역만 노출하고, 내비게이션은 헤더의 메뉴 버튼을 눌렀을 때 펼쳐지는 형태로 축소한다.
- 모든 화면은 PRD NFR-02에 따라 동일한 기능을 두 뷰포트 모두에서 사용할 수 있어야 하며, 모바일 뷰에서는 다단 레이아웃을 단일 컬럼으로 재배치한다.
- 로그인 이후 화면(W-03~W-06)은 공통적으로 상단에 "할일 목록 / 카테고리 관리 / 회원 정보 / 로그아웃" 메뉴를 포함한다.

### 3.1 공통 내비게이션(데스크톱)

```
+--------------------------------------------------------------------+
| [my_Todolist]   할일 목록 | 카테고리 관리 | 회원 정보    [사용자명 v]|
+--------------------------------------------------------------------+
```

- `[사용자명 v]` 클릭: 드롭다운 메뉴가 열리며 "회원 정보 수정", "로그아웃" 항목을 노출한다.
- "로그아웃" 클릭: 시스템은 refresh_token을 무효화하는 요청을 보낸 뒤 저장된 토큰을 삭제하고 로그인 화면(W-02)으로 이동한다.(FR-03)
- API 요청 중 access_token 만료로 401 응답을 받으면, 화면 전환 없이 백그라운드에서 refresh_token으로 토큰 재발급을 시도하고 실패했던 요청을 재시도한다. refresh_token도 만료·무효인 경우에만 로그인 화면으로 이동한다.(FR-13, SC-04)

### 3.2 공통 내비게이션(모바일)

```
+----------------------------------+
| [=]   my_Todolist       [사용자] |
+----------------------------------+
```

- `[=]` 버튼 클릭: 화면 하단 또는 좌측에서 "할일 목록 / 카테고리 관리 / 회원 정보 / 로그아웃" 메뉴가 오버레이 형태로 펼쳐진다.
- 메뉴 항목 선택 시 오버레이가 닫히고 해당 화면으로 이동한다.

## 4. 화면별 와이어프레임

### W-01. 회원가입 화면

**화면 목적**: 신규 사용자가 이메일, 비밀번호, 이름을 입력해 계정을 생성한다.

**관련 FR/유스케이스**: FR-01 / 회원가입 / SC-01(전체 흐름 1단계), SC-08(중복 이메일 예외)

**주요 UI 요소 배치(데스크톱)**

```
+--------------------------------------------------------------------+
|                         my_Todolist                                |
|                                                                      |
|                 +--------------------------------+                  |
|                 |  회원가입                        |                  |
|                 |                                  |                  |
|                 |  이메일                           |                  |
|                 |  [_____________________________] |                  |
|                 |                                  |                  |
|                 |  비밀번호 (영문·숫자 포함 8자 이상)   |                  |
|                 |  [_____________________________] |                  |
|                 |                                  |                  |
|                 |  이름 (1~30자)                     |                  |
|                 |  [_____________________________] |                  |
|                 |                                  |                  |
|                 |  ( 오류 메시지 영역 )               |                  |
|                 |                                  |                  |
|                 |  [       가입하기       ]         |                  |
|                 |                                  |                  |
|                 |  이미 계정이 있으신가요? 로그인      |                  |
|                 +--------------------------------+                  |
+--------------------------------------------------------------------+
```

**주요 UI 요소 배치(모바일)**: 중앙 정렬 카드가 화면 폭 전체(좌우 여백만 유지)로 확장되며, 세로 스택 구조는 데스크톱과 동일하게 유지한다. 상단에는 별도 내비게이션 없이 서비스명만 노출한다.

**주요 인터랙션**

- `[가입하기]` 클릭: 입력값의 형식(이메일 형식, 비밀번호 길이·문자 조합, 이름 길이)을 클라이언트 측에서 우선 검증하고, 서버 응답에서 이메일 중복 오류가 반환되면 오류 메시지 영역에 "이미 사용 중인 이메일입니다"와 같은 메시지를 표시한다(SC-08).
- 가입 성공 시 로그인 화면(W-02)으로 이동하며, 시스템은 내부적으로 해당 사용자의 '기본' 카테고리를 자동 생성한다.
- "로그인" 링크 클릭: 로그인 화면(W-02)으로 이동한다.

### W-02. 로그인 화면

**화면 목적**: 기존 사용자가 이메일과 비밀번호로 인증하고 access_token, refresh_token을 발급받는다.

**관련 FR/유스케이스**: FR-02, FR-13 / 로그인, 토큰 재발급 / SC-01(전체 흐름 2단계), SC-04, SC-11(로그인 실패 예외)

**주요 UI 요소 배치(데스크톱)**

```
+--------------------------------------------------------------------+
|                         my_Todolist                                |
|                                                                      |
|                 +--------------------------------+                  |
|                 |  로그인                          |                  |
|                 |                                  |                  |
|                 |  이메일                           |                  |
|                 |  [_____________________________] |                  |
|                 |                                  |                  |
|                 |  비밀번호                          |                  |
|                 |  [_____________________________] |                  |
|                 |                                  |                  |
|                 |  ( 오류 메시지 영역 )               |                  |
|                 |                                  |                  |
|                 |  [       로그인        ]          |                  |
|                 |                                  |                  |
|                 |  계정이 없으신가요? 회원가입         |                  |
|                 +--------------------------------+                  |
+--------------------------------------------------------------------+
```

**주요 UI 요소 배치(모바일)**: W-01과 동일한 방식으로 카드가 화면 폭 전체로 확장되는 단일 컬럼 레이아웃을 사용한다.

**주요 인터랙션**

- `[로그인]` 클릭: 이메일·비밀번호를 서버로 전송하고, 인증 성공 시 access_token과 refresh_token을 저장한 뒤 할일 목록 화면(W-03)으로 이동한다.
- 인증 실패(이메일 미존재 또는 비밀번호 불일치) 시, 원인을 구분하지 않은 동일한 오류 메시지("이메일 또는 비밀번호가 올바르지 않습니다" 등)를 오류 메시지 영역에 표시한다(BR-11, SC-11).
- 로그인 이후 발급받은 access_token이 만료되면, 사용자가 별도로 인지하지 못한 상태에서 refresh_token을 이용한 재발급이 이루어진다(3.1절 참조, SC-04).

### W-03. 할일 목록 화면(필터링 포함)

**화면 목적**: 로그인한 사용자가 본인의 할일 목록을 조회하고, 카테고리 및 상태(시작 전/진행중/완료/기한초과) 기준으로 필터링한다.

**관련 FR/유스케이스**: FR-08, FR-09 / 할일 목록 조회 / SC-01(전체 흐름 5~7단계), SC-03

**주요 UI 요소 배치(데스크톱)**

```
+--------------------------------------------------------------------+
| [my_Todolist]   할일 목록 | 카테고리 관리 | 회원 정보    [사용자명 v]|
+--------------------------------------------------------------------+
|  카테고리: [전체 v]   상태: [전체][시작 전][진행중][완료][기한초과]  |

+----------------------------------+

|     [수정]  [삭제]                |
+----------------------------------+
|                ...                |
+----------------------------------+
```

상태 필터는 데스크톱에서는 버튼 그룹으로 가로 배치하되, 모바일에서는 공간 절약을 위해 드롭다운(선택형 목록)으로 전환한다. 카드형 목록 항목은 데스크톱·모바일 모두 세로로 나열하되, 모바일에서는 카드 내부 요소(제목, 카테고리, 상태 배지, 기간, 버튼)를 완전한 세로 스택으로 배치한다.

**상태 표시 규칙(텍스트 기반 배지 설명)**

목록의 각 할일 항목 우측(모바일은 상단 우측)에 상태를 나타내는 텍스트 배지를 표시하며, 배지의 색상 라벨로 상태를 구분한다. 상태 판단은 도메인 정의서 5장의 규칙(완료 → 기한초과 → 시작 전 → 진행중 순으로 평가)을 그대로 따른다.

| 상태 | 배지 표기 | 색상 라벨(설명) |
|---|---|---|
| 완료(Completed) | `[완료]` | 회색 계열 배지, 체크 표시 아이콘과 함께 표시하고 제목에 취소선을 적용한다. |
| 기한초과(Overdue) | `[기한초과]` | 적색 계열 배지로 강조하여 지연된 항목임을 즉시 인지할 수 있게 한다. |
| 시작 전(Not Started) | `[시작 전]` | 청색 또는 회청색 계열 배지로, 아직 진행되지 않은 항목임을 나타낸다. |
| 진행중(In Progress) | `[진행중]` | 녹색 계열 배지로, 현재 기간 내에 있는 항목임을 나타낸다. |

완료 처리된 할일은 종료일자가 지났더라도 항상 `[완료]` 배지로만 표시되며 `[기한초과]` 배지와 동시에 나타나지 않는다(BR-7, SC-03).

**주요 인터랙션**

- 카테고리 드롭다운 선택: 선택한 카테고리에 속한 할일만 목록에 재조회한다(전체 선택 시 필터 해제).
- 상태 필터 버튼(데스크톱) 또는 드롭다운(모바일) 선택: 선택한 상태에 해당하는 할일만 재조회한다. 카테고리 필터와 상태 필터는 동시에 적용 가능하다.
- 체크박스 `[ ]` 클릭: 즉시 완료 처리 요청을 보내고, 성공 시 상태 배지를 `[완료]`로 갱신한다. 이미 체크된 항목을 다시 클릭하면 완료를 취소하고 시작일자·종료일자 기준으로 상태를 재계산해 표시한다(FR-12, SC-05).
- `[+ 할일 등록]` 클릭: 할일 등록 화면(W-04, 등록 모드)으로 이동한다.
- `[수정]` 클릭: 해당 할일의 수정 화면(W-04, 수정 모드)으로 이동한다.
- `[삭제]` 클릭: 삭제 확인 대화상자를 노출하고, 확인 시 목록에서 해당 항목을 제거한다(FR-11).

### W-04. 할일 등록/수정 화면(캘린더 포함)

**화면 목적**: 사용자가 제목, 설명, 카테고리, 시작일자·종료일자를 입력해 새 할일을 등록하거나 기존 할일을 수정한다. 시작일자·종료일자는 캘린더 UI로 선택한다.

**관련 FR/유스케이스**: FR-07(등록), FR-10(수정), FR-12(완료 여부 수정) / 할일 등록, 할일 수정, 할일 완료 처리 / SC-01(전체 흐름 4·6단계), SC-05, SC-09(타인 소유 접근 예외), SC-10(종료일자 오류 예외)

**주요 UI 요소 배치(데스크톱)**

```
+--------------------------------------------------------------------+
| [my_Todolist]   할일 목록 | 카테고리 관리 | 회원 정보    [사용자명 v]|
+--------------------------------------------------------------------+
|  < 목록으로                                                          |
|                                                                      |
|  할일 등록 / 할일 수정                                                |
|                                                                      |
|  제목 (1~100자)                                                       |
|  [________________________________________________________]         |
|                                                                      |
|  설명 (선택, 최대 1000자)                                              |
|  [________________________________________________________]         |
|  [________________________________________________________]         |
|                                                                      |
|  카테고리                     시작일자                 종료일자        |
|  [전체 v] (미지정 시 '기본')  [2026-08-20  📅]      [2026-08-30  📅]   |
|                                                                      |
|  (시작일자 또는 종료일자 입력란 클릭 시 아래와 같은 캘린더가 펼쳐짐)     |
|  +----------------------------------+                                |

|                                                                      |
|  ( 오류 메시지 영역: 예) "종료일자는 시작일자 이후여야 합니다." )       |
|                                                                      |
|  [       저장       ]     [   취소   ]                               |
+--------------------------------------------------------------------+
```

**주요 UI 요소 배치(모바일)**

```
+----------------------------------+
| [=]   my_Todolist       [사용자] |
+----------------------------------+
| < 목록으로                        |
|                                    |
| 할일 등록 / 할일 수정               |
|                                    |
| 제목                               |
| [_______________________________] |
|                                    |
| 설명 (선택)                        |
| [_______________________________] |
|                                    |
| 카테고리                           |
| [전체 v]                          |
|                                    |
| 시작일자                           |
| [2026-08-20              📅]      |
|                                    |
| 종료일자                           |
| [2026-08-30              📅]      |
|                                    |
| (캘린더는 전체 화면 오버레이로 표시)|
|                                    |
| 완료 여부   ( ) 미완료  ( ) 완료   |
|                                    |
| [           저장           ]      |
| [           취소           ]      |
+----------------------------------+
```

데스크톱에서는 시작일자·종료일자 입력란이 가로로 나란히 배치되고, 캘린더는 해당 입력란 아래 팝오버 형태로 펼쳐진다. 모바일에서는 시작일자·종료일자 입력란이 세로로 각각 배치되며, 캘린더는 화면 전체를 덮는 오버레이(모달) 형태로 표시되어 좁은 화면에서도 날짜 선택이 용이하도록 한다.

**주요 인터랙션**

- 시작일자/종료일자 입력란 클릭: 캘린더가 펼쳐지고, 날짜를 클릭하면 해당 입력란에 선택한 날짜가 채워지고 캘린더가 닫힌다(FR-07, FR-10, 도메인 정의서 REQ-F04).
- `[저장]` 클릭: 제목 필수 여부, 종료일자가 시작일자 이상인지(BR-6)를 클라이언트 측에서 우선 검증한 뒤 서버에 요청한다. 서버에서 검증 오류가 반환되면(예: 종료일자가 시작일자보다 빠른 경우, SC-10) 오류 메시지 영역에 안내 문구를 표시하고 저장을 진행하지 않는다.
- 카테고리를 선택하지 않고 저장하면 시스템은 해당 사용자의 '기본' 카테고리로 자동 지정한다(BR-3).
- 등록 모드에서는 "완료 여부" 항목을 노출하지 않으며(신규 할일은 항상 미완료로 생성), 수정 모드에서만 노출하여 완료 처리·완료 취소가 가능하도록 한다. 완료로 전환하면 `completedAt`이 현재 일시로 기록되고, 완료를 취소하면 `completedAt`이 초기화되며 상태가 재계산된다(FR-12, SC-05).
- 수정 화면 진입 시, 요청한 할일이 본인 소유가 아닌 경우 시스템은 403 오류를 반환하며 화면은 "접근 권한이 없습니다"와 같은 안내와 함께 목록 화면으로 돌아가는 버튼만 표시한다(BR-2, SC-09).
- `[취소]` 클릭: 입력 내용을 저장하지 않고 할일 목록 화면(W-03)으로 돌아간다.

### W-05. 카테고리 관리 화면

**화면 목적**: 사용자가 할일 분류용 카테고리를 등록·수정·삭제한다.

**관련 FR/유스케이스**: FR-05, FR-06 / 카테고리 등록, 카테고리 수정, 카테고리 삭제 / SC-01(전체 흐름 3단계), SC-02, SC-07

**주요 UI 요소 배치(데스크톱)**

```
+--------------------------------------------------------------------+
| [my_Todolist]   할일 목록 | 카테고리 관리 | 회원 정보    [사용자명 v]|
+--------------------------------------------------------------------+
|  카테고리 관리                                                       |
|                                                                      |
|  새 카테고리 이름 (1~20자)                                             |
|  [___________________________]  [ 추가 ]                             |
|                                                                      |
|  +----------------------------------------------------------------+ |
|  | 기본                                    (수정 불가) (삭제 불가) | |
|  +----------------------------------------------------------------+ |
|  +----------------------------------------------------------------+ |
|  | 학교 과제                               [수정]      [삭제]     | |
|  +----------------------------------------------------------------+ |
|  +----------------------------------------------------------------+ |
|  | 업무                                    [수정]      [삭제]     | |
|  +----------------------------------------------------------------+ |
|                                                                      |
|  ( 오류 메시지 영역: 예) "이미 사용 중인 카테고리 이름입니다." )        |
+--------------------------------------------------------------------+
```

**주요 UI 요소 배치(모바일)**

```
+----------------------------------+
| [=]   my_Todolist       [사용자] |
+----------------------------------+
| 카테고리 관리                      |
|                                    |
| 새 카테고리 이름                    |
| [_______________________________] |
| [            추가            ]    |
|                                    |
| 기본                (수정/삭제 불가)|
+----------------------------------+
| 학교 과제                          |
| [수정]           [삭제]           |
+----------------------------------+
| 업무                               |
| [수정]           [삭제]           |
+----------------------------------+
```

모바일에서는 카드 내부의 이름과 버튼이 데스크톱처럼 한 줄에 배치되지 못하므로, 이름을 상단에 표시하고 `[수정]`, `[삭제]` 버튼을 하단에 가로로 배치하는 2줄 구성으로 전환한다.

**주요 인터랙션**

- `[추가]` 클릭: 입력한 이름이 사용자 내에서 중복되지 않는지 검증한 뒤 카테고리를 생성하고 목록에 즉시 반영한다(FR-05).
- '기본' 카테고리 항목은 항상 최상단에 고정 표시되며, `[수정]`/`[삭제]` 버튼 대신 "수정 불가", "삭제 불가" 안내 문구만 노출한다(BR-4).
- 일반 카테고리의 `[수정]` 클릭: 이름 입력란이 인라인 편집 상태로 전환되고, 저장 시 사용자 내 이름 중복 여부를 재검증한다(SC-07).
- 일반 카테고리의 `[삭제]` 클릭: 삭제 확인 대화상자에 "삭제 시 소속 할일은 '기본' 카테고리로 이동합니다"라는 안내 문구를 함께 표시하고, 확인 시 카테고리를 삭제하며 소속 할일을 '기본' 카테고리로 일괄 이관한다(BR-5, SC-02).

### W-06. 회원 정보 수정 화면

**화면 목적**: 로그인한 사용자가 본인의 이름과 비밀번호를 수정한다. 이메일은 수정 대상에서 제외된다.

**관련 FR/유스케이스**: FR-04 / 회원 정보 수정 / SC-06

**주요 UI 요소 배치(데스크톱)**

```
+--------------------------------------------------------------------+
| [my_Todolist]   할일 목록 | 카테고리 관리 | 회원 정보    [사용자명 v]|
+--------------------------------------------------------------------+
|  회원 정보 수정                                                       |
|                                                                      |
|  이메일                                                                |
|  [ user@example.com               ] (수정 불가)                        |
|                                                                      |
|  이름 (1~30자)                                                         |
|  [_____________________________]                                    |
|                                                                      |
|  새 비밀번호 (영문·숫자 포함 8자 이상, 변경 시에만 입력)                     |
|  [_____________________________]                                    |
|                                                                      |
|  새 비밀번호 확인                                                       |
|  [_____________________________]                                    |
|                                                                      |
|  ( 오류 메시지 영역 )                                                  |
|                                                                      |
|  [       저장       ]                                                |
+--------------------------------------------------------------------+
```

**주요 UI 요소 배치(모바일)**: 각 입력란이 화면 폭 전체를 차지하는 단일 컬럼으로 배치되며, 항목 순서와 구성은 데스크톱과 동일하다.

**주요 인터랙션**

- 이메일 입력란은 항상 읽기 전용으로 표시되어 수정할 수 없다(BR-9).
- `[저장]` 클릭: 이름 길이(1~30자)와 비밀번호 형식(영문·숫자 포함 8자 이상)을 검증하고, 새 비밀번호와 확인란이 일치하는지 확인한 뒤 서버에 저장을 요청한다(BR-10). 비밀번호 입력란을 비워 두면 이름만 변경하고 비밀번호는 유지한다.
- 저장 성공 시 완료 안내 메시지를 표시하고, `updatedAt`이 갱신된 최신 정보를 화면에 반영한다(SC-06).

## 5. 화면 흐름 요약

```
[로그인 안 됨] --(회원가입 W-01)--> [로그인 W-02]
[로그인 W-02] --(로그인 성공)--> [할일 목록 W-03]

[할일 목록 W-03] --(+ 할일 등록)--> [할일 등록/수정 W-04, 등록 모드] --(저장/취소)--> [할일 목록 W-03]
[할일 목록 W-03] --(수정)--> [할일 등록/수정 W-04, 수정 모드] --(저장/취소)--> [할일 목록 W-03]
[할일 목록 W-03] <--(상단 내비게이션)--> [카테고리 관리 W-05]
[할일 목록 W-03] <--(상단 내비게이션)--> [회원 정보 수정 W-06]
[모든 로그인 이후 화면] --(로그아웃)--> [로그인 W-02]
```

access_token 만료로 인한 재인증(FR-13)은 화면 전환 없이 백그라운드에서 처리되며, refresh_token까지 만료된 경우에만 로그인 화면(W-02)으로 강제 이동한다.
